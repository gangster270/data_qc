# 일일 환경데이터 QC 루틴 프롬프트

> Cowork Routine 에 그대로 붙여 넣는 프롬프트. 매 실행이 새 세션에서 시작될 수 있으므로
> 맥락 없이도 완결되게 작성한다. `<자료경로>` 는 현장에 맞게 수정한다.

---

data_qc 저장소에서 오늘의 환경데이터 QC 점검을 수행해줘.

## 1. 실행

```bash
cd <저장소경로>
# 1) 새로 내려받은 파일을 통합 아카이브에 반영(없으면 그대로 통과)
python scripts/build_archive.py --env "<자료경로>/**/*.xlsx" "<자료경로>/**/*.csv" \
       --out outputs/archive
# 2) 아카이브 전체를 로거별로 점검
python scripts/run_monitor.py --archive outputs/archive --by-logger --lookback 7 --json
```

종료코드: 0=정상, 1=WARN 있음, 2=CRITICAL 있음.

## 2. 읽을 것

- 위 명령의 JSON 요약(등급별 건수, 규칙별 건수, 로거별 건수 `by_logger`, 결측 timestamp 수)
- `outputs/reports/qc_report_<오늘날짜>.md` (센서 상태표 + 신규 알림)
- **어제 리포트** `outputs/reports/qc_report_<어제날짜>.md` — 비교용

## 3. 판단 기준

1. **신규 / 지속 / 해소**를 구분한다.
   - 신규: 어제 없던 이상 → 현장 조치 대상
   - 지속: 어제도 있던 이상 → 조치가 안 된 것인지, 알림만 반복되는 것인지 구분
   - 해소: 어제 있었으나 오늘 사라진 이상 → 한 줄로 확인만
2. 아래 규칙은 **오탐 가능성**을 먼저 검토한다.
   - `R07_night_light` : 야간보광(NI/SL) 처리구면 정상 → 무시
   - `R09_logger_offline` : 수동 내려받기 운영이면 정상 → 내려받기 주기 확인
   - `R05_spike`, `R04_flatline` : 최근 센서 청소·재삽입 기록이 있으면 개입 영향
     (`outputs/sensor_verification_log.csv` 의 최근 7일 기록 확인)
3. CRITICAL 은 원인 후보를 데이터로 좁힌다.
   - 여러 변수가 동시에 끊겼는가 → 로거·전원 문제
   - 한 변수만 이상한가 → 해당 센서·커넥터 문제
   - 같은 날짜에 다른 로거도 끊겼는가 → 현장 전체 사건(정전·작업)

## 4. 보고 방식

- **모든 항목 정상이면 아무것도 보내지 말고**, 한 줄로 "정상"만 기록하고 종료한다.
  (무알림이 정상 신호다. 매일 오는 알림은 곧 무시된다.)
- CRITICAL 이 있으면 다음 형식으로 알린다.

```
[환경데이터 QC] <현장명> <날짜>
■ 조치 필요 (CRITICAL n건)
  1. <무엇이/언제부터> — 원인 후보: <…> / 조치: <…>
■ 지속 중 (n건)  ※ 이미 알린 건
■ 참고: 결측 timestamp <n>건, 최근 7일 수신율 <xx>%
```

- WARN 만 있으면 주간 점검일(월요일)에 한 번만 모아서 알린다.

## 5. 마무리

- 오늘 판단한 내용(신규/지속/해소, 조치 권고)을 `outputs/reports/qc_report_<오늘날짜>.md`
  하단에 `## 판단` 섹션으로 덧붙인다.
- 데이터 파일·설정을 임의로 수정하지 않는다. 원자료는 덮어쓰지 않는다.
- 새 이상 유형이 반복되면(같은 규칙이 3일 연속) 임계값 조정을 제안하되, 직접 바꾸지는 않는다.
