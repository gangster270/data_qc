# 대시보드 사용법 — 어디서 무엇을 보는가

`streamlit run app/streamlit_app.py` 로 여는 웹 화면 안내.
**설치 없이 결과만 보고 싶다면** 9번 항목(파일로 확인하기)만 봐도 된다.

---

## 0. 실행 (처음 한 번)

```bash
# 1) 저장소 받기
git clone https://github.com/gangster270/data_qc.git
cd data_qc

# 2) 필요한 패키지 설치 (파이썬 3.10 이상)
pip install -r requirements.txt

# 3) 대시보드 실행
streamlit run app/streamlit_app.py
```

실행하면 터미널에 아래처럼 주소가 뜬다. 브라우저가 자동으로 열리며,
열리지 않으면 **Local URL 을 브라우저 주소창에 붙여넣는다.**

```
  Local URL: http://localhost:8501
  Network URL: http://192.168.0.12:8501     ← 같은 공유기의 다른 PC·태블릿에서 접속
```

- 끄려면 터미널에서 **Ctrl + C**.
- 코드를 고쳤으면 브라우저에서 **F5**(또는 우측 상단 ⋮ → Rerun).
- 포트가 겹치면: `streamlit run app/streamlit_app.py --server.port 8502`

> 연구실 서버에 띄워두고 여럿이 보려면 `--server.address 0.0.0.0` 을 붙이고
> Network URL 을 공유한다.

## 1. 화면은 3단계로 흘러간다

```
왼쪽 사이드바              화면 위쪽 탭
1단계 · 자료 넣기   →   2️⃣ 상태 점검   →   3️⃣ 결과 만들기
                        (문제 없나?)      (분석용 표 만들기)
                                 ↘  📦 쌓인 자료
                                    (매주 쌓기 · 지난 결과 다시 받기)
```

파일을 올리기 전에는 시작 안내 화면(1️⃣·2️⃣·3️⃣ 카드 3장)만 보인다.
**왼쪽에 파일을 올리는 순간** 탭 5개가 나타난다.

---

## 2. 1단계 · 자료 넣기 (왼쪽 사이드바)

**"어디에 있는 자료인가요?"** 에서 셋 중 하나를 고른다.

| 선택 | 언제 쓰나 |
|---|---|
| **내 컴퓨터 파일** | 기본. 로거에서 내려받은 파일을 그대로 끌어다 놓는다(여러 개 동시 가능) |
| **서버 폴더** | 연구실 서버에 파일이 쌓여 있을 때. `data/*.xlsx` 처럼 위치를 적고 **불러오기** |
| **모아둔 전체 자료** | `build_archive.py` 로 통합해 둔 폴더에서 **구역을 골라** 불러온다(8-1 참고) |

읽고 나면 사이드바에 초록 상자로 **읽기 완료** 요약이 뜬다 —
기간·일수, 측정 항목 개수, 기록 간격. 그 아래 항목 이름이 한글로 나열된다.

- **자동으로 알아본 내용 고치기** — 접혀 있다. 시간 칸·기록 간격·항목 인식이
  실제와 다를 때만 열어서 `파일의 칸 이름` → `이 칸은 무엇인가요?` 를 지정하고 **적용**.
- **읽은 파일 목록** — 어떤 파일이 몇 줄 읽혔는지.

**ZL6 전용이 아니다.** 국산 로거·자체 기록 CSV·엑셀 어느 것이든
시간(또는 날짜+시간) 칸만 있으면 다음을 자동 인식한다.

- 구분자(`,` `;` 탭)·인코딩(UTF-8·CP949)·헤더 위치(상단 설명행이 있어도 됨)
- 날짜와 시간이 **따로 있는 칸**(`날짜` + `시각`) → 하나로 합침
- **기록 간격**(1·5·10·15·30·60분 …) → 광량 합계·결측률·고착 판정에 자동 반영
- 항목명 표기 차이(`SoilTemp` / `soil_temp` / `Soil Temperature` / `배지 온도` → 모두 배지온도)
- 시트가 여러 개(`Config 1`, `Config 2`)로 나뉜 엑셀도 전부 읽어 합침
- **모르는 항목도 버리지 않는다** — 수온·pH·풍속·관수량 등은 이름 그대로 보존되어
  하루별 평균/최저/최고까지 계산되고, 결측·고착 감시도 함께 받는다.

## 3. 2단계 · 자료 상태 점검 (탭 `2️⃣ 상태 점검`)

**아무것도 누르지 않아도 된다.** 화면을 열면 바로 점검이 끝나 있다.

1. **맨 위 한 줄 결론** — 셋 중 하나만 뜬다.
   - 🟢 **이상 없습니다** → 바로 `3️⃣ 결과 만들기` 로 넘어가면 된다.
   - 🟠 **확인해 볼 것 N건** → 급하지 않다. 주간 점검 때 함께 본다.
   - 🔴 **조치가 필요한 문제 N건** → 아래 "무엇을 하면 되나요?" 를 본다.
2. **무엇을 하면 되나요?** — 문제가 **규칙별로 접힌 칸**으로 묶여 있다.
   칸을 펼치면 세 가지가 나온다.
   - 제목: 무슨 일이 났는지(예: *"낮인데 광센서가 어둡습니다"*)
   - **무슨 뜻인가요?** — 왜 이런 게 뜨는지
   - **어떻게 하나요?** — 현장에서 할 일
   - 그 아래 표: 어느 항목이 언제 그랬는지
3. **한눈에 보기** — 항목별 지표 카드. 신호등(🟢🟠🔴)과 최근값·수신율이 함께 보이고,
   카드 아래 **작은 그래프(스파크라인)** 가 최근 3일 흐름을 보여준다.
   **선이 빨간 항목이 점검이 필요한 항목**이다.
4. **이상이 난 구간 확인** — 항목을 고르면 그 항목의 곡선 위에
   **이상이 감지된 시간대가 빨간 띠**로 덮인다. 띠에 마우스를 올리면 무슨 문제인지 나오고,
   빨간 점선은 센서가 낼 수 있는 값의 한계선이다. *언제부터 이상해졌는지*를 눈으로 잡을 때 쓴다.
5. **항목별 상태** — 항목마다 `정상 · 주의 · 위험` 과 수신율·최근값.
   *수신율 = 그 기간에 들어와야 할 기록 중 실제로 들어온 비율.*
6. **날짜별로 얼마나 비었나** — 날짜 × 항목 히트맵. 진한 칸일수록 그날 많이 빈 것.
7. **직접 눈으로 보기** — 항목을 골라 실제 곡선 확인.
8. **알림 보내기** — `지금 보내기`(중복은 쿨다운으로 억제) / `내용만 미리보기`.
   Slack·메일 외에 **카카오톡**으로도 받을 수 있다(⚙️ 설정 탭 참고).

맨 아래 초록 테두리 안내가 다음에 할 일을 짚어 준다.

> 참고: 화면에는 한글 제목만 보이지만, 안쪽 규칙 코드(`R01`~`R13`)가 궁금하면
> `docs/sensor_verification_routine.md` 의 대응표를 본다.

## 4. 3단계 · 결과 만들기 (탭 `3️⃣ 결과 만들기`)

수작업으로 하던 시차 매칭을 대체하는 화면. **조사 날짜만 정하면 끝난다.**

1. (선택) **한 로거로 여러 처리구를 재고 있나요?** — 접힌 칸.
   센서마다 처리구가 다르면 체크하고 로거를 고른다
   (`config/sensor_map.yaml` 에 포트↔처리구를 적어두어야 함).
2. **조사 날짜만 정해 주세요** — 세 가지 중 선택.
   - `시작일과 간격만 알려주기` : 첫 조사일 + 며칠마다 + (횟수 또는 마지막 날짜)
   - `조사한 날짜를 직접 적기` : 실제 조사일을 쉼표로 나열(밀린 날짜 그대로 반영)
   - `생육조사 파일 올리기` : 조사일 칸(`date` 등)이 있는 csv/xlsx → 생육값까지 병합
3. **첫 구간은 언제부터 계산할까요?** — 보통 정식일을 넣는다.
4. **만들어진 결과**
   - 한 줄 결론: `구간 N개 완성` (자료가 부족한 구간이 있으면 *주의* 표시)
   - **① 어떤 기간이 어느 조사일에 붙었나요?** — 조사일 ↔ 사용한 환경 기간
   - **② 구간별 환경 요약** ← 분석에 쓰는 표. 품질이 '정상'이 아닌 구간은 빼는 게 좋다
   - **③ 생육값 + 환경** — 생육 파일을 올렸을 때만. **최종 표**
5. **내려받기** — `구간환경.csv` · `생육_환경_병합.csv` · `환경정리결과.xlsx`(한 번에)
6. **이번 결과 남겨두기** — 회차로 저장하면 📦 쌓인 자료 탭에서 다시 받을 수 있다.
7. **☁️ GitHub 에도 올려두기** — 준비가 되어 있으면 날짜 폴더로 레포에 바로 올라간다
   (설정 방법은 ⚙️ 설정 탭 맨 아래).

표는 기본적으로 **핵심 칸만 한글 이름**으로 보인다.
원래 열 이름과 나머지 계산값이 필요하면 표 아래 **전체 열 보기**를 펼친다.

세부 계산 조건(기준온도, 시차 일수, 이상값 제외 등)은 **⚙️ 세부 설정**
접힌 칸 안에 있다. 손대지 않아도 기본값으로 계산된다.

### 빈 칸(결측)이 있을 때 — 세부 설정 안

| 고르는 것 | 언제 쓰나 |
|---|---|
| **그대로 두기** (기본) | 대부분의 경우. 빈 칸을 빼고 평균을 낸다 |
| **짧게 빈 곳만 채우기** | 센서가 잠깐씩 튀어 구멍이 많을 때. 정한 시간(기본 60분) **이하로 빈 곳만** 앞뒤 값으로 채운다 |
| **빈 칸이 있는 줄은 빼기** | 센서끼리 값을 짝지어 비교할 때만. 센서 하나만 고장나도 그 시각 전체가 빠진다 |

왜 짧은 곳만 채우나 — PPFD·일사량은 **하루치를 더해서** 광량(DLI)을 낸다.
잠깐 빈 곳을 비워 두면 그날 광량이 실제보다 적게 나온다. 반대로 반나절씩 빈 곳을
직선으로 이으면 **없던 자료를 지어내는 것**이라 해가 뜨고 지는 모양이 통째로 망가진다.
그래서 짧은 구멍만 채우고, 긴 구멍은 빈 칸으로 남겨 '자료가 부족한 구간'으로 표시한다.
몇 개를 채웠는지는 화면에 바로 나오고, **항목별 결측 처리 내역** 에서 확인할 수 있다.

## 5. 📦 쌓인 자료 — 매주 올린 자료가 모이는 곳

**매주 새 파일을 올릴 때마다 여기에 이어붙는다.** 처음부터 다시 할 필요가 없다.

1. **① 이번에 올린 자료 넣기** — 왼쪽에 올린 파일을 **📦 보관함에 쌓기** 한 번으로 넣는다.
   - 같은 파일을 두 번 올려도 **중복되지 않는다**(내용이 같으면 건너뜀).
   - 기간이 겹쳐도 같은 구역·같은 시각은 **한 줄로 합쳐진다**.
   - 원본 파일도 `outputs/archive/uploads/` 에 그대로 남아, 나중에 전부 다시 계산할 수 있다.
2. **② 지금까지 쌓인 자료** — 구역별 기간·행수, 올린 파일 이력, 전체 자료 내려받기.
3. **③ 지난 결과 다시 받기** — 회차별로 저장해 둔 결과를 골라 그대로 내려받는다.
   저장은 `3️⃣ 결과 만들기` 화면 맨 아래 **💾 이번 결과 저장**에서 한다.

쌓아 둔 자료로 점검·정리를 하려면 왼쪽에서 **모아둔 전체 자료**를 고르고 구역을 선택한다.

### 매주 하는 일을 명령 한 줄로

```bash
# 첫 주 — 조사일 기준을 한 번만 알려준다(config/survey.yaml 에 기억됨)
python scripts/weekly_update.py --env "data/신규/*" \
       --survey-start 2026-04-01 --survey-interval 10 --survey-count 12

# 그 다음 주부터
python scripts/weekly_update.py --env "data/신규/*"
```

한 번에 ①쌓기 ②점검(알림·리포트) ③정리(시차 매칭)까지 하고,
결과를 `outputs/results/<날짜>/` 회차 폴더에 남긴다. 지난 회차는 지워지지 않는다.

- 구역 이름을 새로 지정한 뒤 전부 다시 계산: `--rebuild`
- 회차 폴더 이름 붙이기: `--label 3주차`
- 점검·정리만 건너뛰기: `--skip-monitor` / `--skip-preprocess`

## 6. 🔬 센서 점검 — "센서를 믿어도 되나?"

1. **① 점검 일정** — 센서별 다음 점검일·지연 여부(기록이 없으면 그렇게 알려준다)
2. **② 두 센서 비교하기** — 두 센서를 하루 나란히 둔 뒤 편차·MAE·상관 r·합격 판정
3. **③ 점검 결과 남기기** — 폼에 넣으면 편차·합격 여부가 자동 계산되어 기록에 쌓임
4. **④ 점검 이력** — 반복 기록에서 연간 드리프트 추정

## 7. ⚙️ 설정

### 🏷️ 로거 번호 ↔ 구역 이름

표의 **구역 칸을 직접 눌러 이름을 적고**, 아래 **💾 구역 이름 저장**을 누른다.
여덟 대든 열 대든 한 번에 적고 한 번에 저장한다.

- 어느 로거인지 헷갈리면 **재는 항목** 칸을 본다 — `광량(PPFD)`만 있는 것, `일사량`이
  있는 것처럼 로거마다 달라서 현장에서 구분할 수 있다.
- **여러 로거에 같은 이름**을 주면 그 로거들이 한 구역 자료로 합쳐진다
  (예: 배지 센서 로거와 광 센서 로거를 둘 다 `3구역`).
- 아는 것만 채우고 나머지는 비워 두어도 된다. 비워 둔 로거는 번호 그대로 따로 관리된다.
- 이름은 언제든 바꿀 수 있다.

**이름을 바꾼 뒤에는 🔄 쌓인 자료 다시 묶기를 눌러야** 이미 쌓아 둔 자료가 새 이름으로
다시 묶인다(새로 올리는 파일은 누르지 않아도 새 이름으로 들어간다).
보관해 둔 원본으로 처음부터 다시 계산하므로 몇 번을 눌러도 결과는 같고,
쌓인 자료가 줄어들 상황이면 **아무것도 바꾸지 않고 이유를 알려 준다**
(보관함에 원본이 없는 로거가 있을 때).

### 그 밖

- **경보 기준** — `config/qc_config.yaml` 을 읽어 보여주는 확인용 화면.
  값을 바꾸려면 그 파일을 편집하고 브라우저에서 F5.
- **알림 보내는 곳** — 채널별 상태(콘솔·파일·Slack·메일·카카오톡)와 **필요한 환경변수**,
  그리고 테스트 발송. 📱 **카카오톡으로 받으려면** 칸에 준비 절차가 적혀 있다.
- **☁️ GitHub 자동 저장** — 토큰·레포·라이브러리 준비 상태를 한 줄로 보여주고,
  **🔌 연결 확인** 단추로 실제 접속을 시험한다. 처음 설정하는 방법도 이 칸 안에 있다.
  결과를 올릴 때는 **그때 쓴 설정(`qc_config_snapshot.yaml`)** 도 함께 올라가,
  나중에 "이 결과는 어떤 기준으로 계산했더라" 를 되짚을 수 있다.

## 8. 자주 겪는 상황

| 증상 | 원인·해결 |
|---|---|
| "날짜/시간 열을 찾지 못했습니다" | 파일 상단에 설명행이 너무 많거나 시간 칸이 텍스트가 아님 → 시간 칸 이름을 `Timestamp`·`일시`·`날짜`+`시간` 으로 맞춘다 |
| 항목이 엉뚱하게 인식됨 | 사이드바 **자동으로 알아본 내용 고치기**에서 해당 칸의 의미를 직접 지정 |
| 기록 간격이 이상하게 잡힘 | 파일에 중복·불규칙 시각이 많은 경우. `config/qc_config.yaml` 의 `site.interval_minutes` 에 숫자를 직접 지정하면 고정된다 |
| 알림이 너무 많이 뜸 | 처리구가 다른 반복 센서 편차(`R10`)는 기본 꺼져 있다. 야간보광 중이면 `night_light_enabled: false` 유지 |
| 표에 필요한 칸이 안 보임 | 표 아래 **전체 열 보기**를 펼친다 |
| 표가 잘려 보임 | 표 오른쪽 끝을 드래그하거나, 표 우측 상단의 전체화면 아이콘 사용 |
| 브라우저에 아무것도 안 뜸 | 터미널에 `Local URL` 이 있는지 확인, 방화벽·다른 포트 사용 여부 확인 |

## 8-1. 보유한 환경데이터 전부 모으기 (통합 아카이브)

파일이 여러 로거·여러 번 내려받기로 흩어져 있다면 먼저 한 곳에 모은다.

```bash
# data/ 아래 모든 파일(하위 폴더 포함)을 하나로
python scripts/build_archive.py --env "data/**/*.xlsx" "data/**/*.csv" --out outputs/archive

# 새로 내려받은 파일이 생기면 그것만 넣고 다시 실행 → 기존 마스터에 이어붙음
python scripts/build_archive.py --env "data/신규/*.xlsx" --out outputs/archive
```

- **로거 번호를 파일 안에서 읽어 구역별로 묶는다** — 파일명이 매번 달라져도(`260703_22094002.csv`)
  같은 로거는 같은 구역으로 이어진다. 번호↔구역 이름은 `config/logger_registry.yaml` 에 기억된다:

  ```bash
  # 한 번만 지정하면 이후 자동 적용. 같은 이름을 주면 여러 로거가 한 구역으로 합쳐진다
  python scripts/build_archive.py --zone "22094002=3구역" --zone "z6-20917=3구역" --list-zones
  ```
  대시보드 ⚙️ 설정 탭의 **🏷️ 로거 번호 ↔ 구역 이름**에서도 지정할 수 있다.
- 한 구역에 로거가 여러 대면 **같은 시각의 값이 한 행으로 합쳐진다**(기록 시각이 몇 초 달라도
  기록 간격 격자에 맞춰 정렬). 같은 변수를 두 로거가 재면 `ppfd`, `ppfd__rep2` 로 둘 다 보존.
- 센서 구성이 바뀌어 엑셀 시트가 `Config 1`, `Config 2` 로 나뉘어도 **전부 읽어 합친다**
  (열은 포트 기준으로 이름이 붙어 구성이 달라도 같은 포트끼리 이어짐).
- 형식·인코딩·기록간격·변수명을 자동 인식해 **날짜순 정렬 + 변수 표준화 + 중복 정리**
- `env_master.csv`(원자료 보존)와 `env_master_clean.csv`(범위이탈 결측처리 + 격자정합) 두 벌 생성
- 대시보드 사이드바에서 `모아둔 전체 자료` 를 고르면 이 마스터를 그대로 불러 쓴다
- 모니터링도 아카이브 전체를 로거별로 한 번에 점검:
  `python scripts/run_monitor.py --archive outputs/archive --by-logger`

## 9. 대시보드 없이 파일로만 확인하기

터미널만으로도 같은 결과를 얻는다(자동 실행·정기 리포트에 적합).

```bash
# 통합: 보유한 모든 환경데이터를 하나로
python scripts/build_archive.py --env "data/**/*.xlsx" --out outputs/archive

# 전처리: 조사일을 직접 정해 시차 매칭(생육 파일 없이도 가능)
python scripts/run_all_loggers.py --archive outputs/archive --by-treatment \
       --survey-start 2026-04-01 --survey-interval 10 --survey-count 6 --out outputs/all

# 전처리: 생육 파일이 있으면 병합까지
python scripts/run_all_loggers.py --archive outputs/archive --growth data/growth.csv --out outputs/all

# 모니터링: 아카이브 전체를 로거별로 점검 + 알림
python scripts/run_monitor.py --archive outputs/archive --by-logger --lookback 7
```

생성되는 파일

| 파일 | 내용 |
|---|---|
| `outputs/daily_env_summary.csv` | 일별 환경 요약 |
| `outputs/env_interval_summary.csv` | 생육 구간별 환경 요약 |
| `outputs/merged_env_growth.csv` | **생육 + 환경 병합(분석 투입용)** |
| `outputs/preprocess_report.xlsx` | 위 전부 + 열 매핑·결측·실행 요약 |
| `outputs/reports/qc_report_YYYY-MM-DD.md` | 그날의 QC 리포트(알림이 없어도 생성) |
| `outputs/reports/alerts_YYYY-MM-DD.jsonl` | 알림 이력 |

매일 자동 실행은 `cowork/COWORK_ROUTINE.md` 참조.
