# 대시보드 사용법 — 어디서 무엇을 보는가

`streamlit run app/streamlit_app.py` 로 여는 웹 화면 안내.
**설치 없이 결과만 보고 싶다면** 4번 항목(파일로 확인하기)만 봐도 된다.

---

## 0. 실행 (처음 한 번)

```bash
# 1) 저장소 받기
git clone https://github.com/gangster270/data_qc.git
cd data_qc

# 2) 필요한 패키지 설치 (파이썬 3.10 이상)
pip install -r requirements.txt

# 3) 대시보드 실행
streamlit run app/streamlit_app.py
```

실행하면 터미널에 아래처럼 주소가 뜬다. 브라우저가 자동으로 열리며,
열리지 않으면 **Local URL 을 브라우저 주소창에 붙여넣는다.**

```
  Local URL: http://localhost:8501
  Network URL: http://192.168.0.12:8501     ← 같은 공유기의 다른 PC·태블릿에서 접속
```

- 끄려면 터미널에서 **Ctrl + C**.
- 코드를 고쳤으면 브라우저에서 **F5**(또는 우측 상단 ⋮ → Rerun).
- 포트가 겹치면: `streamlit run app/streamlit_app.py --server.port 8502`

> 연구실 서버에 띄워두고 여럿이 보려면 `--server.address 0.0.0.0` 을 붙이고
> Network URL 을 공유한다.

## 1. 왼쪽 사이드바 — 파일 넣는 곳

| 항목 | 설명 |
|---|---|
| **데이터 입력** | `파일 업로드`(내 PC 파일 끌어다 놓기) · `서버 경로`(경로 입력) · **`통합 아카이브`**(전체 환경데이터 마스터에서 로거 선택) |
| **파일 선택** | `.xlsx/.xls/.csv/.txt/.tsv`, **여러 개 동시 선택 가능**(같은 로거의 분할 파일이면 자동 병합) |
| **중복 센서 처리** | `first`(기본) / `mean`(같은 위치 반복일 때만) / `keep`(모두 보존) |
| **🔍 자동 인식 결과 / 수정** | 시간 열·기록 간격·인식된 변수 목록. 인식이 틀렸을 때 여기서 열 의미를 바꾼다 |
| **로드 로그** | 어떤 파일이 몇 행 읽혔는지 |

**ZL6 전용이 아니다.** 국산 로거·자체 기록 CSV·엑셀 어느 것이든
시간(또는 날짜+시간) 열만 있으면 다음을 자동 인식한다.

- 구분자(`,` `;` 탭)·인코딩(UTF-8·CP949)·헤더 위치(상단 설명행이 있어도 됨)
- 날짜와 시간이 **따로 있는 열**(`날짜` + `시각`) → 하나로 합침
- **기록 간격**(1·5·10·15·30·60분 …) → DLI·결측률·고착 판정에 자동 반영
- 변수명 표기 차이(`SoilTemp` / `soil_temp` / `Soil Temperature` / `배지 온도` → 모두 배지온도)
- **모르는 변수도 버리지 않는다** — 수온·pH·풍속·관수량 등은 이름 그대로 보존되어
  일별 평균/최저/최고까지 계산되고, 결측·고착 감시도 함께 받는다.

자동 인식이 틀렸을 때만 사이드바 **🔍 자동 인식 결과 / 수정**에서
`원본 열` 을 고르고 `이 열의 의미`를 지정한 뒤 **적용**을 누른다.

## 2. 화면 위쪽 탭 4개 — 목적별로 나뉜다

### 📊 모니터링 — "지금 문제가 있나?"

| 위치 | 보는 것 |
|---|---|
| 상단 숫자 5개 | 전체 알림 / 🔴CRITICAL / 🟠WARN / 결측 timestamp / 관측 일수 |
| **센서 상태** 표 | 변수별 수신율·결측률·범위이탈·최근값, `정상·주의·위험` |
| **알림 목록** | 규칙·변수·기간·내용. 우측 아래 **알림 CSV 다운로드** |
| **일자별 결측률** | 날짜 × 변수 히트맵. 진한 칸 = 그날 그 센서가 비어 있던 날 |
| **시계열 확인** | 변수를 골라 실제 곡선 확인(의심 구간 눈으로 검증) |
| **알림 발송** | `지금 발송`(쿨다운 적용) / `리포트 미리보기`(발송 없음) |
| 맨 아래 접힌 칸 | 열 매핑 상세 · 연속 결측 구간 목록 |

**CRITICAL 이 0 이면 그날은 손댈 게 없다.** 있으면 알림 목록의 규칙 이름
(`R01_timestamp_gap` 등)을 `docs/sensor_verification_routine.md` 의 대응표와 대조한다.

### 🔁 전처리(생육 매칭) — "환경을 생육조사 간격으로 묶기"

수작업으로 하던 작업을 대체하는 화면. 위에서 아래로 순서대로 진행된다.

1. **설정 줄** — GDD 기준온도, **시차(일)**, 고정창 사용, 범위 이탈값 결측 처리, 불완전일 제외
2. **처리구별 집계**(체크박스) — 한 로거의 센서가 처리구별로 꽂혀 있을 때 사용
   (`config/sensor_map.yaml` 에 포트↔처리구를 적어두어야 함)
3. **① 일별 요약** — 10분(또는 다른 간격) 자료가 하루 단위로 접힌 표
4. **② 조사일 기준 정하기** — 세 가지 중 선택
   - `시작일 + 간격` : 정식일과 7·10일 간격, 횟수(또는 종료일)만 넣으면 조사일이 자동 생성
   - `조사일 직접 입력` : 실제 조사일을 쉼표로 나열(현장 사정으로 밀린 날짜 그대로 반영)
   - `생육 파일 업로드` : `date` 열이 있는 csv/xlsx (조사간격 자동 인식, 생육값까지 병합)
5. **③ 구간 정의** — 각 조사일에 어떤 환경 기간이 매칭됐는지
6. **④ 구간별 환경 요약** / **⑤ 생육 + 환경 병합** ← **이게 최종 결과물**
7. **다운로드** — `merged_env_growth.csv`(분석용) 또는 Excel 일괄
8. 맨 아래 **환경↔생육 상관 빠르게 보기** — 경향 확인용(정식 검정은 R 로)

### 🔬 센서 정기검증 — "센서를 믿어도 되나?"

1. **① 검증 기한 현황** — 센서별 다음 점검일·지연 여부
2. **② 현장 상호비교** — 두 센서를 24시간 나란히 둔 뒤 편차(bias)·MAE·상관 r·합격 판정
3. **③ 검증 결과 기록** — 폼에 입력하면 편차·합격 여부가 자동 계산되어 로그에 쌓임
4. **④ 검증 이력·드리프트** — 반복 기록에서 연간 드리프트 추정

### ⚙️ 설정 — "임계값이 지금 얼마인가?"

`config/qc_config.yaml` 을 읽어 보여주는 **확인용** 화면이다.
값을 바꾸려면 그 파일을 편집하고 브라우저에서 F5. 알림 채널 테스트 발송도 여기서 한다.

## 3. 자주 겪는 상황

| 증상 | 원인·해결 |
|---|---|
| "날짜/시간 열을 찾지 못했습니다" | 파일 상단에 설명행이 너무 많거나 시간 열이 텍스트가 아님 → 사이드바에서 파일을 다시 확인하거나, 시간 열 이름을 `Timestamp`·`일시`·`날짜`+`시간` 으로 맞춘다 |
| 변수가 엉뚱하게 인식됨 | 사이드바 **🔍 자동 인식 결과 / 수정**에서 해당 열의 의미를 직접 지정 |
| 기록 간격이 이상하게 잡힘 | 파일에 중복·불규칙 시각이 많은 경우. `config/qc_config.yaml` 의 `site.interval_minutes` 에 숫자를 직접 지정하면 고정된다 |
| 알림이 너무 많이 뜸 | 처리구가 다른 반복 센서 편차(`R10`)는 기본 꺼져 있다. 야간보광 중이면 `night_light_enabled: false` 유지 |
| 표가 잘려 보임 | 표 오른쪽 끝을 드래그하거나, 표 우측 상단의 전체화면 아이콘 사용 |
| 브라우저에 아무것도 안 뜸 | 터미널에 `Local URL` 이 있는지 확인, 방화벽·다른 포트 사용 여부 확인 |

## 3-1. 보유한 환경데이터 전부 모으기 (통합 아카이브)

파일이 여러 로거·여러 번 내려받기로 흩어져 있다면 먼저 한 곳에 모은다.

```bash
# data/ 아래 모든 파일(하위 폴더 포함)을 하나로
python scripts/build_archive.py --env "data/**/*.xlsx" "data/**/*.csv" --out outputs/archive

# 새로 내려받은 파일이 생기면 그것만 넣고 다시 실행 → 기존 마스터에 이어붙음
python scripts/build_archive.py --env "data/신규/*.xlsx" --out outputs/archive
```

- 형식·인코딩·기록간격·변수명을 자동 인식해 **날짜순 정렬 + 변수 표준화 + 중복 정리**
- `env_master.csv`(원자료 보존)와 `env_master_clean.csv`(범위이탈 결측처리 + 격자정합) 두 벌 생성
- 대시보드 사이드바에서 `통합 아카이브` 를 고르면 이 마스터를 그대로 불러 쓴다
- 모니터링도 아카이브 전체를 로거별로 한 번에 점검:
  `python scripts/run_monitor.py --archive outputs/archive --by-logger`

## 4. 대시보드 없이 파일로만 확인하기

터미널만으로도 같은 결과를 얻는다(자동 실행·정기 리포트에 적합).

```bash
# 통합: 보유한 모든 환경데이터를 하나로
python scripts/build_archive.py --env "data/**/*.xlsx" --out outputs/archive

# 전처리: 조사일을 직접 정해 시차 매칭(생육 파일 없이도 가능)
python scripts/run_all_loggers.py --archive outputs/archive --by-treatment \
       --survey-start 2026-04-01 --survey-interval 10 --survey-count 6 --out outputs/all

# 전처리: 생육 파일이 있으면 병합까지
python scripts/run_all_loggers.py --archive outputs/archive --growth data/growth.csv --out outputs/all

# 모니터링: 아카이브 전체를 로거별로 점검 + 알림
python scripts/run_monitor.py --archive outputs/archive --by-logger --lookback 7
```

생성되는 파일

| 파일 | 내용 |
|---|---|
| `outputs/daily_env_summary.csv` | 일별 환경 요약 |
| `outputs/env_interval_summary.csv` | 생육 구간별 환경 요약 |
| `outputs/merged_env_growth.csv` | **생육 + 환경 병합(분석 투입용)** |
| `outputs/preprocess_report.xlsx` | 위 전부 + 열 매핑·결측·실행 요약 |
| `outputs/reports/qc_report_YYYY-MM-DD.md` | 그날의 QC 리포트(알림이 없어도 생성) |
| `outputs/reports/alerts_YYYY-MM-DD.jsonl` | 알림 이력 |

매일 자동 실행은 `cowork/COWORK_ROUTINE.md` 참조.
