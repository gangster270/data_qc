# 환경 센서 정기 검증 루틴 (SOP)

시설재배 환경 로거(METER ZL6 + ATMOS 14 / TEROS 12 / SQ-521 / PYR) 기준.
자동 모니터링(`scripts/run_monitor.py`)이 **이상 발생을 알려주는 장치**라면,
이 루틴은 **이상이 없다는 것을 주기적으로 증명하는 절차**다. 둘은 대체 관계가 아니다.

기록은 모두 `outputs/sensor_verification_log.csv` 한 파일에 남기고,
대시보드(🔬 센서 정기검증 탭)에서 기한·드리프트를 확인한다.

---

## 1. 주기 요약

| 주기 | 코드값 | 항목 | 소요 | 담당 |
|---|---|---|---|---|
| 매일(자동) | — | 자동 QC 모니터링 리포트 확인 | 2분 | 데이터 담당 |
| 주 1회 | `visual_check` | 육안 점검 · 청소 · 설치상태 확인 | 20분 | 포장 관리자 |
| 월 1회 | `cross_check` | 센서 상호비교(24시간 나란히 설치) | 1일 방치 + 10분 | 데이터 담당 |
| 분기 1회 | `reference_check` | 기준기 대조, EC 표준액 검정 | 1시간 | 데이터 담당 |
| 2년 1회 | `factory_calibration` | 제조사 재교정 / 센서 교체 판단 | 배송 포함 2~4주 | 연구책임 |

주기 값은 `config/qc_config.yaml` → `verification.schedule_days` 에서 조정한다.

## 2. 매일 — 자동 모니터링 확인 (2분)

1. 아침에 도착한 QC 리포트(Slack/메일 또는 `outputs/reports/qc_report_YYYY-MM-DD.md`)를 연다.
2. **CRITICAL 이 있으면 당일 조치**, WARN 은 주간 점검 때 확인한다.
3. 조치한 내용은 검증 로그에 `check_type=visual_check`, `action=` 으로 남긴다.

알림 등급별 1차 판단:

| 규칙 | 흔한 실제 원인 | 1차 조치 |
|---|---|---|
| `R01_timestamp_gap` | 로거 전원·SD·통신 두절, 정전 | 현장 확인, 배터리·케이블 점검 |
| `R02_missing_ratio` | 특정 센서 커넥터 접촉 불량 | 포트 재체결, 방수캡 확인 |
| `R03_out_of_range` | 배선 단선(-99.9 등 오류코드) | 케이블·커넥터 교체 |
| `R04_flatline` | 센서 고착, 로거 정지, 배지 이탈 | 센서 재삽입, 로거 리셋 |
| `R05_spike` | 접촉 불량·전자기 노이즈 | 배선 정리, 접지 확인 |
| `R06_daytime_dark` | 광센서 탈락·완전 차폐·오염 | 위치 복원, 확산캡 청소 |
| `R08_rh_saturated` | 필터 결로·오염 | 필터 교체, 통풍 확인 |
| `R09_logger_offline` | 배터리 방전, 통신 장애 | 배터리 교체, 통신 재설정 |
| `R11_transmittance_drop` | 렌즈 오염, 차광막·구조물 그늘 | 청소 후 재확인, 위치 조정 |
| `R12_error_value` | 센서 출력 오류값 | 해당 기간 데이터 제외 표시 |
| `R13_heat_event` | 환기 실패·차광 미작동(실제 고온) | **센서 오류 아님** — 현장 상황 확인, 해당 구간 생육 해석에 반영 |

## 3. 주 1회 — 육안 점검 · 청소 (`visual_check`)

체크리스트 (모두 확인 후 로그 1건 기록):

- [ ] **SQ-521(PPFD)**: 확산캡 먼지·물때·응결 → 증류수 적신 부드러운 천으로 닦고 마른 천으로 마무리.
      **수평(기포수준기)** 확인. 작물 그림자·구조물 그늘이 지지 않는지 확인.
- [ ] **PYR(일사량)**: 돔 오염·긁힘 확인, 수평 확인.
- [ ] **ATMOS 14(온습도)**: 방사차폐(라디에이션 실드) 내부 먼지·거미줄 제거, 필터 변색 확인.
      직사광·난방기 온풍이 직접 닿지 않는 위치인지 확인.
- [ ] **TEROS 12(배지온도·수분·EC)**: 침 삽입 깊이·밀착 상태, 배지 수축으로 인한 들뜸 확인.
      EC 가 0 으로만 나오면 먼저 배지수분을 본다 — vwc<10% 면 건조 때문이며 센서 고장이 아니다.
      들떠 있으면 **같은 깊이·같은 방향**으로 재삽입하고 로그에 반드시 기록(값이 계단식으로 변함).
- [ ] **로거 본체**: 배터리 잔량(≥30%), 방수함 내부 결로, 케이블 피복 손상, 커넥터 체결.
- [ ] 다운로드 주기 확인(ZENTRA Cloud 동기화 여부 또는 수동 내려받기).

> 청소·재삽입은 **데이터에 계단(step)을 만드는 개입**이다. 반드시 일시를 기록해야
> 나중에 "그날 값이 왜 튀었는지" 재구성할 수 있다.

## 4. 월 1회 — 센서 상호비교 (`cross_check`)

교정 기준기가 없어도 **동일 조건 병렬 설치 비교**로 드리프트를 잡아낼 수 있다.

절차
1. 검증 대상 센서 옆(30 cm 이내, 같은 높이·방향)에 **기준 센서**(신품 또는 최근 교정품)를 설치한다.
2. **24시간 이상**(광센서는 맑은 날 포함) 동시 기록한다.
3. 대시보드 → 🔬 센서 정기검증 → **② 현장 상호비교**에서 두 열을 선택해 실행한다.
   (CLI: `sensor_check.cross_check(df, "temp", "temp__rep2", "temp", cfg)`)
4. 산출되는 bias / MAE / r / 회귀기울기와 합격 기준을 확인하고 결과를 로그에 저장한다.

합격 기준 (`config/qc_config.yaml` → `verification.tolerance`)

| 변수 | 허용 편차 | 비고 |
|---|---|---|
| 온도 | ±0.5 ℃ | 방사차폐 동일 조건에서 비교 |
| 상대습도 | ±3 %RH | 고습(>90%)에서는 ±5%까지 허용 |
| 배지온도 | ±0.5 ℃ | 같은 깊이 필수 |
| 배지수분(VWC) | ±3 %(=0.03 m³/m³) | METER TEROS 는 % 로 출력. 같은 배지·같은 관수 조건 |
| EC | ±0.3 mS/cm | 표준액 검정과 병행 |
| PPFD | ±5 % (주간 평균 기준) | 야간 0 구간 제외하고 비교 |
| 일사량 | ±5 % | 맑은 날 정오 기준 |

판정별 조치
- **합격**: 로그에 `result=pass` 기록 후 원위치.
- **불합격(편차 초과)**: ① 청소 후 재비교 → ② 그래도 초과하면 보정계수 적용 여부 검토
  (기울기·절편을 로그에 남기고 분석 단계에서 적용) → ③ 두 배 이상 초과 시 교체·재교정 의뢰.
- **상관 r < 0.95**: 단순 오프셋이 아니라 센서 응답 자체가 깨진 상태 → 즉시 교체 검토.

## 5. 분기 1회 — 기준기 대조 (`reference_check`)

| 대상 | 기준기 | 방법 | 합격 |
|---|---|---|---|
| 온습도 | 교정성적서 있는 휴대용 온습도계(또는 아스만 통풍건습계) | 그늘·통풍 조건에서 10분 간격 6회 비교 | 온도 ±0.5℃, 습도 ±3% |
| PPFD | 교정된 휴대용 광량자계 | 맑은 날 11~13시, 센서면 같은 높이·수평에서 5회 | 상대편차 ±5% |
| 일사량 | 인근 기상관측소 또는 교정 일사계 | 맑은 날 일적산 비교 | ±10% (거리 보정 고려) |
| 배지 EC | 표준액(1.413 / 12.88 mS/cm) | 표준액 25℃ 담금 측정 | ±0.3 mS/cm |
| 배지수분 | 중량법(코어 채취 → 105℃ 24h 건조) | 3반복 평균과 센서값 비교 | ±3 %(=0.03 m³/m³) |

추가로 분기마다 다음을 확인한다.
- 로거 **시각 동기화**(시계 드리프트 → timestamp 어긋남). 표준시와 1분 이상 차이나면 재설정하고
  그 시점을 로그에 남긴다(데이터 시간축 보정 근거).
- **투과율 재산출**: 내부 PPFD ÷ 외부 일사환산 PPFD 의 최근 30일 중앙값을 기록.
  값이 계속 떨어지면 피복재 노화·오염이며, 이 값은 `agri-ppfd-gap-fill` 의 결측 보정 계수로 그대로 쓰인다.

## 6. 2년 1회 — 제조사 재교정 (`factory_calibration`)

- **SQ-521(광량자센서)**: 제조사 권장 2년. 대표적으로 연 2~3% 감도 저하가 보고되므로,
  장기 시험(2년 이상)에서는 재교정 없이 연도 간 광량을 직접 비교하지 않는다.
- **PYR(일사계)**: 2년.
- **ATMOS 14**: 공장교정 후 무교정 사용이 원칙이나, 상호비교에서 반복 불합격 시 교체.
- **TEROS 12**: 배지 특성에 따른 오차가 크므로, 사용 배지(코이어·펄라이트 등)에 대한
  **현장 중량법 검정 곡선**을 1회 이상 만들어 두고 그 관계식을 유지·갱신한다.

재교정·교체 시에는 반드시 로그에 남기고, 전처리 단계에서 **센서 교체 시점 전후를
같은 시계열로 이어붙이지 않도록** 표시한다(계단 발생 구간).

## 7. 기록 양식

`templates/sensor_calibration_log.csv` (= `outputs/sensor_verification_log.csv` 스키마)

| 열 | 설명 |
|---|---|
| `date` | 검증일 (YYYY-MM-DD) |
| `logger_id` | 로거 ID (z6-21068 등) |
| `sensor_id` | 센서 제조번호 또는 포트 |
| `sensor_type` | SQ-521 / ATMOS 14 / TEROS 12 / PYR |
| `variable` | temp / rh / soil_temp / vwc / ppfd / solar / ec |
| `check_type` | visual_check / cross_check / reference_check / factory_calibration |
| `reference_value` | 기준기(또는 기준센서) 값 |
| `sensor_value` | 대상 센서 값 |
| `deviation` | 센서값 − 기준값 (자동 계산) |
| `rel_deviation` | 상대편차(광센서) |
| `result` | pass / fail (허용오차 기준 자동 판정) |
| `operator` | 점검자 |
| `action` | 조치(청소/재삽입/보정계수/교체) |
| `note` | 비고 — **개입 시각과 내용을 반드시 남길 것** |

입력 경로는 두 가지다.
- 대시보드 🔬 탭 → **③ 검증 결과 기록** 폼 (권장, 편차·판정 자동 계산)
- CSV 직접 편집 (현장에서 종이로 받아 일괄 입력할 때)

## 9. 데이터 무결성 원칙

1. **원자료는 절대 덮어쓰지 않는다.** 보정은 항상 별도 열/별도 파일로 만든다.
2. 센서 청소·재삽입·교체·시각 재설정은 **모두 개입 이벤트**다. 기록 없이 하지 않는다.
3. 결측을 임의로 채우지 않는다. 보간·대체는 방법과 구간을 명시하고
   (§11 결측 처리 정책, `agri-ppfd-gap-fill` 참조) `qc_status` 로 구분한다.
4. 검증 로그가 없는 기간의 데이터는 "검증되지 않은 데이터"로 보고서에 명시한다.

## 10. 이상 판별 기준 (물리 기준 · 통계 기준)

판별은 두 층으로 나눈다. **물리 기준**은 "센서가 낼 수 없는 값"이라 무조건 오류이고,
**통계 기준**은 "값 자체는 가능하지만 그렇게 나올 리가 없는 패턴"이라 현장 확인이 필요하다.
둘을 섞으면 진짜 사건(환기 실패로 인한 고온 등)을 오류로 지워 버리게 된다.

### 10-1. 물리 기준 — 범위를 벗어나면 오류값

`config/qc_config.yaml` → `sensors` 의 기본 추천값. **센서 측정사양** 기준으로 넓게 잡는다.

| 변수 | 허용 범위 | 급변 기준(10분당) | 이 범위를 벗어나는 대표 원인 |
|---|---|---|---|
| 온도 | −40 ~ 80 ℃ | 5 ℃ | 배선 단선(−99.9 등 오류코드), 커넥터 침수 |
| 상대습도 | 0 ~ 100 % | 30 %RH | 필터 파손, A/D 오류 |
| 배지온도 | −40 ~ 60 ℃ | 4 ℃ | 센서 배지 이탈, 케이블 손상 |
| 배지수분(VWC) | 0 ~ 75 %　※ | 15 % | 배지 이탈(공기 중 측정 → 0 근처), 침수 |
| PPFD | 0 ~ 2,500 µmol m⁻² s⁻¹ | 1,500 | 센서 탈락, 직사광 반사, 배선 노이즈 |
| 일사량 | 0 ~ 1,400 W m⁻² | 800 | 상동 |
| EC | 0 ~ 20 mS/cm | 3 | 전극 오염, 배지 완전 건조 |
| CO₂ | 250 ~ 3,000 ppm | 500 | 센서 워밍업 미완, 교정 소실 |

※ METER TEROS 12 는 체적수분을 **%(=m³/m³ ×100)** 로 내보낸다. m³/m³ 로 환산해 쓰면 0.75.

> **작물 기준으로 좁게 잡지 말 것.** 예를 들어 온도 상한을 40℃로 잡으면 환기 실패로
> 실제 70℃까지 오른 **진짜 사고**가 오류값으로 지워진다. 작물 위험 수준은 별도 규칙
> (`R13_heat_event`: 일최고 기온 45℃ / 배지온도 40℃)으로 **경보만** 하고 값은 남긴다.

### 10-2. 통계 기준 — 값은 가능하지만 패턴이 이상할 때

| 판별 | 기본 추천값 | 판정 근거 | 흔한 원인 |
|---|---|---|---|
| 기록 누락(`R01`) | 연속 60분 → 주의 / 360분 → 위험 | 기대 기록 수 대비 실제 수신 | 전원·SD·통신 두절 |
| 결측률(`R02`) | 일 10% → 주의 / 50% → 위험 | 변수별 일 결측 비율 | 커넥터 접촉 불량 |
| 고착(`R04`) | 동일값 연속 6시간(광 3시간) | 분산 = 0 구간 길이 | 센서 고착, 로거 정지 |
| 급변(`R05`) | 위 표의 급변 기준, 하루 3회 이상 | 인접 시점 차분 | 접촉 불량, 전자기 노이즈 |
| 주간 암흑(`R06`) | 9~15시 PPFD 최대 < 20 | 주간 광량 하한 | 광센서 탈락·완전 차폐 |
| 습도 포화(`R08`) | RH ≥ 99% 가 12시간 연속 | 포화 지속시간 | 필터 결로·오염 |
| 로거 두절(`R09`) | 마지막 관측 120분 / 720분 경과 | 최종 수신 경과시간 | 배터리 방전 |
| 투과율 급락(`R11`) | 최근 3일 중앙값 < 기준 30일의 70% | 내부 PPFD ÷ 외부 환산 PPFD | 렌즈 오염, 차광막·구조물 그늘 |

**고착 판정의 예외** — 야간 PPFD·일사량 0 연속과, 배지가 마른 구간의 EC 0 출력은
정상이다(`qc.flatline_ignore_zero`). 이 예외를 빼면 매일 아침 오탐이 쌓여 알림을 무시하게 된다.

**야간 보광(NI/SL) 시험 중이라면** `qc.night_light_enabled` 를 반드시 `false` 로 둔다.
켜 두면 정상적인 야간 보광이 전부 "야간 광 검출" 경보로 잡힌다.

### 10-3. 임계값을 현장에 맞게 조정하는 법

1. 정상이라고 확신하는 **최근 30일 자료**로 먼저 돌려 본다.
2. 알림이 뜬 건을 하나씩 현장 확인해 **오탐/진탐**으로 분류한다.
3. 오탐이면 그 규칙의 임계값을 완화하고, **왜 완화했는지 사유를 같이 기록**한다.
4. 조정 후에는 과거 자료로 다시 돌려 **진짜 사건이 여전히 잡히는지** 확인한다.

임계값을 낮춰 알림을 없애는 것이 목적이 아니다. **현장 담당자가 알림을 계속 읽게 만드는 것**이
목적이며, 하루 몇 건 이상 뜨면 이미 무시당하기 시작한다.

## 11. 결측 처리 정책

결측을 채울지 말지는 **변수의 성격**과 **구멍의 길이**로 정한다.
대시보드(3️⃣ 결과 만들기 → 세부 설정)와 `preprocess.fill_missing()` 이 이 정책을 따른다.

| 구멍 길이 | 처리 | 이유 |
|---|---|---|
| ≤ 60분(기본 설정값) | 선형보간으로 채움 | 센서가 잠깐 튄 수준. 특히 PPFD·일사량은 **하루치를 적산**해 DLI 를 내므로 비워 두면 그날 광량이 실제보다 적게 나온다 |
| > 60분 | 채우지 않고 결측 유지 | 반나절을 직선으로 이으면 일출·일몰 곡선과 관수 주기가 통째로 왜곡된다. **없던 자료를 지어내는 것** |
| 자료의 맨 앞·맨 뒤 | 채우지 않음(외삽 금지) | 앞뒤 실측값이 없으면 근거가 없다 |

- 보간 한계시간은 `preprocess.missing_limit_minutes` 로 조정한다.
- 보간 건수는 항상 **처리 내역 표**로 남고, 남은 결측은 일별 `completeness` 와
  구간별 `quality_flag` 에 그대로 드러난다. 보고서에는 **보간 여부와 구간을 명시**한다.
- 긴 결측을 굳이 메워야 한다면 직선 보간이 아니라 **외부 관측소 자료 + 투과율**로
  복원한다(`agri-ppfd-gap-fill`). 이때도 원자료 열과 복원 열은 분리해 둔다.
- "빈 칸이 있는 줄 삭제"는 센서 한 개 고장으로 그 시각의 **모든 항목**이 함께 날아가므로,
  센서 간 값을 짝지어 비교할 때 외에는 쓰지 않는다.
